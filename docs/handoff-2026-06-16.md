## Текущая модель anti-tamper (важно держать в голове)

Фундамент: под **тем же пользователем** (same-user) полная устойчивость к
удалению невозможна (хук защищает сам себя — циклично). Поэтому два яруса:

1. **Дефолт (same-user): hard-deny очевидного + tamper-evidence.** Очевидно-злое
   режется из коробки (даже в observe). Что под одним пользователем заблокировать
   нельзя (удаление записи хука полной перезаписью settings.json) — **фиксируется
   мгновенно на сервере** (`sensor.hook_drift`, `sensor.silent`,
   `sensor.hooks_removed`; быстрый sweep раз в 60с). Сервер за границей привилегий.
2. **Опционально `ccguard harden` (root): настоящая устойчивость.** Хуки в
   root-owned `managed-settings.json` Claude Code (подтверждено по бинарю
   v2.1.178) + неизменяемые шим/policy. Агент под своим юзером хук не уберёт.

Детально: `docs/anti-tamper.md`.

## Открытые решения / следующие шаги (на выбор)

1. **Поле-тест hardened-тира** под root на реальной машине: `ccguard harden | sudo bash`,
   затем под своим юзером попытаться убрать хук/перезаписать шим → ждём отказ ОС.
   (Генерация скрипта проверена; живое enforcement — за тобой.)
2. **`dangerous.*` политика**: сейчас `rm -rf /`, `mkfs`, `sudo -i`, `curl|bash`
   под текущей `~/.ccguard/policy.yaml` **НЕ** hard-блокируются (это ярус,
   зависящий от политики). Решить: включать ли эти правила из коробки.
3. **`read_pi_block`** (блок чтения файла с инъекцией в PreToolUse) по умолчанию
   **выключен** — инъекция ловится только на audit-пути (находкой), не режется.
   Решить: включать ли по умолчанию (риск ложных срабатываний на security-доках).
4. **bin-only deploy** (self-contained бинарь вместо venv-python) — закрывает
   последний residual hardened-тира (подмена venv-python). Отдельная задача.
5. **Быстрый sweep кадэнс** — сейчас 60с (`SENSOR_SWEEP_INTERVAL_SECONDS`); при
   желании настроить.

## Сознательно отложено (не трогаем сейчас)

- **РФ-рынок / локальные росс-модели** (GigaChat/YandexGPT-бэкенд, реестр, ФСТЭК) —
  поворот потом. Итог РФ-buyer-ревью — в `git log` и памяти сессии.
- **SIEM-эмиттер + алертинг** (KUMA/MaxPatrol/webhook/Telegram) — отложено (нет
  push-уведомлений, находки только pull через API).
- **observe-by-default** — НАМЕРЕННАЯ тест-настройка, не дефект (мы тестируем).
  Не флипать на enforce без явного решения.

## Принципы (не отступаем)

«Никаких декораций»: каждая фича работает end-to-end и проверена; tamper-evidence
(честная фиксация факта) лучше декоративной «защиты», которую тривиально обходят.
TDD, регресс зелёный после куска, работаем прямо в master, термины — в переводе.
