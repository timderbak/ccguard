# ccguard UI — редизайн (design doc)

> Дата: 2026-06-08 · Статус: дизайн согласован, ждёт ревью спеки перед планом реализации.

## 1. Проблема и цель

Бэкенд умеет много (детект-движки, таксономия ATLAS/ATT&CK/OWASP ТЗ-08, цепочки-сценарии ТЗ-09, карта покрытия, индикаторы, корреляции), но в UI **этого не видно**: `coverage_service`, `chain_engine`, `Detector`/`Technique`/`ThreatIndicator` не вызываются ни одним web-роутом. Текущий экран «ничего не понятно».

**Цель:** новый UI, который (а) даёт понятную постуру «всё ли под контролем» на одном экране, (б) выводит наружу всё построенное (карта покрытия, цепочки, индикаторы, корреляции), (в) выглядит как премиальный продукт.

## 2. Аудитория

- **Основная (≈70%, профиль A):** сам владелец — «вайбкодер» на 1–2 своих машинах. Вопрос экрана: что мой агент делает, что поймали, всё ли под контролем.
- **Витрина (≈30%, профиль C):** показать мощь детекта/покрытия (демо/продажи). Воплощается в hero-странице «Карта покрытия» и богатом дашборде.
- НЕ SOC-воркфлоу: без тяжёлого триаж-процесса, тикетов, мульти-аналитиков.

## 3. Визуальное направление («Fortexa-скин»)

Тёмная премиальная «бенто»-сетка. Референсы: Fortexa (цвет/шрифт/gauge), CyberSphere (точечная сетка тактик, kill-chain timeline), CY·FOCUS (KPI-стрип с дельтами, лента событий, ранжированные бары).

- **Фон:** почти-чёрный `#0b0810` с фиолетовым radial-свечением сверху-справа.
- **Карточки:** `#16121f` / `#1b1626`, радиус 20px, тонкая граница `#ffffff0f`.
- **Акцент (основной):** фиолетово-magenta градиент `#7c3aed → #e455c8`. Семантика: фиолетовый = нейтральные метрики/покрытие.
- **Семантика угроз:** оранжево-красный `#ff6a1a`/`#ff5470` = блокировки/угрозы/«требует внимания»; зелёный `#34d399` = «покрыто/норма/позитивная дельта».
- **Jewel-иконки** в кружках (фиолетовый/синий/оранжевый/розовый) — только на мелких категорийных иконках.
- **Шрифт:** Plus Jakarta Sans (400–800). Цифры — tabular, bold, letter-spacing −1px.
- **Иконки:** тонкие линейные SVG, без эмодзи.
- Это **новая тёмная тема вместо текущей светлой** «blueprint». Старые `cc-*` классы заменяются; светлую тему не сохраняем (single theme).

Утверждённый макет дашборда зафиксирован в `.superpowers/brainstorm/.../dashboard-fortexa.html`.

## 4. Информационная архитектура (каркас ②)

Левый сайдбар, 3 смысловые группы (продолжает текущий 2-групповой паттерн). Паттерн взаимодействия — **дрилдаун** (сводка → клик → деталь).

- **ПОСТУРА:** Дашборд · Карта покрытия
- **ДЕТЕКТ:** Атаки (цепочки) · Находки · Индикаторы · Корреляции · Аномалии · Аудит
- **УПРАВЛЕНИЕ:** Машины · Фиды (на согласовании) · Политика · Настройки

(Вариант верхней навигации как у Fortexa отклонён — у нас 13 пунктов, их держит сайдбар.)

## 5. Экраны (назначение · компоненты · источник данных)

1. **Дашборд** — постура за один взгляд.
   - Светофор-шапка (под контролем / янтарь / красный) + режим OBSERVE/ENFORCE + время синхронизации.
   - **KPI-стрип** (CY·FOCUS): детекты за неделю · заблокировано сегодня · открытые угрозы · фиды на согласовании — с дельта-пиллами и мини-чартами; кликабельны (дрилдаун).
   - **Сегментный gauge «Оценка MCP-поверхности»** (Fortexa) — см. §7.
   - **Таблица «Обзор поверхности»** — MCP/skills/hooks инвентарь с риск-баром, источником (npm/github/local), доступами (Bash/Net/Write), «замечен».
   - **Лента «Недавняя активность»** (CY·FOCUS) — последние находки/блоки/policy-apply/фиды.
   - Данные: `FindingRecord`, `risk_service`, инвентарь/baselines, `proposed_signals`, новый surface-score (§7).

2. **Карта покрытия** — hero/витрина (профиль C).
   - **Точечная сетка тактик × фреймворк** (CyberSphere) — залитые кружки по `coverage_by_tactic`.
   - **Разбивка по типу контроля** PREV/DETECT/SCOPE (`coverage_by_control_type`) — «где блокируем / видим / ограничиваем».
   - **Kill-chain timeline** по стадиям.
   - Клик по технике → `coverage_detail` (чем покрыта: индикаторы + детекторы + crosswalk ATLAS≈ATT&CK≈OWASP). Вне-скоупа — приглушённый блок, не как дыры.
   - Данные: `coverage_service` (covered/uncovered/by_tactic/by_control_type/coverage_detail/crosswalk_for).

3. **Атаки (цепочки)** — сработавшие сценарии как последовательности.
   - Список `ChainMatch` → раскрытие в kill-chain последовательность (initial→cred→exfil), какие сигналы/техники совпали на каждом шаге, severity, control_type=DETECT.
   - Реестр сценариев (`chain_seed_service.list_scenarios`) со статусом (активен / armed-waiting).
   - Данные: `chain_engine`, `chain_seed_service`, findings `ioa.chain.*`.

4. **Находки** — обогащённая лента (рестайл существующей).
   - Добавить к строке: техника/фреймворк, control_type, привязку к сценарию/цепочке, дрилдаун в деталь. Фильтры severity/scope/rule_id/machine.
   - Данные: `FindingRecord` + обогащение таксономией.

5. **Индикаторы** — каталог `ThreatIndicator`.
   - Поиск/фильтр по типу (path/command/host/safe), источнику, технике, control_type. Раздел «на согласовании» (proposed-signals / Путь-2).
   - Данные: `ThreatIndicator`, `IndicatorTechniqueMapping`.

6. **Корреляции** — реестр детекторов.
   - 5 детекторов (`Detector`) + их привязки к техникам (`DetectorTechniqueMapping`), control_type, rule_ids, связь со сценариями.
   - Данные: `Detector`, `DetectorTechniqueMapping`.

7. **Машины / Машина** — рестайл существующих (инвентарь, baselines/drift, риск, top-actors).
8. **Аномалии · Аудит · Политика · Настройки** — рестайл существующих под новый скин (логика не меняется).

## 6. Библиотека компонентов (переиспользуемые партиалы)

Сегментный radial-gauge · KPI-карточка (дельта-пилл + мини-чарт) · точечная сетка-хитмап · kill-chain timeline · ранжированные бары · риск-score-бар · элемент ленты активности · severity-пилл · technique-chip · таблица инвентаря · дрилдаун-обёртка.

## 7. «Оценка MCP-поверхности» (новый скоринг)

Новая метрика 0–100: насколько безопасна MCP/skill/hook-поверхность. **Стартовая формула (калибруется на реальных данных):**
`score = 100 − clamp( Σ риск(артефакт) )`, где риск артефакта растёт от: опасных гранованных tools (Bash/Net/Write), недоверенного источника (unknown/npm vs ccguard/local), TOFU-drift, divergence по флоту, отсутствия в allowlist.
Реализация — новый маленький сервис `surface_score_service` (только чтение инвентаря/baselines). **Формула — открытый вопрос, помечен для калибровки.**

## 8. Технический подход

- Стек не меняем: FastAPI + Jinja2 + HTMX. Новая тема — через CSS-переменные в `base.html` + новый набор партиалов.
- Новые роуты в `web/routes.py`, **читающие** `coverage_service`/`chain_engine`/`chain_seed_service`/`Detector`/`ThreatIndicator` (детект-движки НЕ трогаем — только чтение).
- Тесты: текущие render-тесты на нестрогих строковых ассертах — рефактор шаблонов безопасен; copy-lock«строки обновляем в том же PR. Каждый новый экран — со своим integration-тестом (рендер + привязка данных), как в `test_web_smoke.py`.
- Работа в master, инкрементальными коммитами, регресс зелёный.

## 9. Фазирование

- **Фаза 1 (каркас + витрина):** новая тема (base.html + компоненты) → **Дашборд** → **Карта покрытия**. Даёт «понятно» + showcase.
- **Фаза 2 (детект наружу):** Атаки/цепочки → Индикаторы → Корреляции → обогащение Находок.
- **Фаза 3 (рестайл хвостов):** Машины/Аномалии/Аудит/Политика/Настройки под новый скин; опц. surface-score калибровка.

Каждая фаза — отдельный план реализации (writing-plans) и набор коммитов.

## 10. Вне скоупа / отложено

- **AI-аналитик** карточка (чат-копайлот) — заманчивая витрина, но отдельный трек (нужен LLM-проводка); не в этом редизайне.
- Гео-карта угроз (CY·FOCUS) — не применима (1–2 машины), заменена ранжированными барами по техникам/MCP.
- Верхняя навигация (Fortexa) — отклонена в пользу сайдбара ②.
- Логика детект-движков, enforce, схемы БД — не трогаем.
